# Owned Smart Reader — source-review core 0.3.15

An independent JavaScript library and CLI for document observations, classification,
grouping, source-bound fields, region rereading, and human corrections. It has no
runtime dependencies, network calls, storage, UI, trucking state, or OCR provider.

Profiles cover the app's trucking document catalog, including RateCons, BOLs,
PODs, invoices, receipts, maintenance, permits, driver and business records.
See [document coverage and references](DOCUMENT-COVERAGE.md). Classification and
extraction use source-backed rules. Unsupported layouts remain for review.
The neural text recognizer is developed separately in `experiments/owned-ocr`.

## Use without the app

```js
import {readDocument, textObservation} from './src/index.js';
const result = readDocument({
  documentId: 'my-document',
  pages: [{
    id: 'original-page-1',
    number: 1,
    observations: [textObservation([
      'INVOICE', 'Invoice No: INV-17', 'Vendor: Example Company',
      'Subtotal: 100.00', 'Tax: 8.25', 'Total: 108.25', 'Currency: USD',
    ].join('\n'))],
  }],
});
```

From the repository root:

```bash
node packages/smart-reader-core/bin/read.mjs input.json > reading.json
node --test packages/smart-reader-core/test/*.test.mjs
```

The CLI accepts the same input JSON, including observations generated by our
Python recognizer. It writes structured JSON and has no external API dependency.

## Input and evidence

Pages are ordered by their position in `pages`; page IDs identify the original
page and must remain stable across reorderings. A retry is another observation on
the same page. Each observation has a unique ID and an explicit source name.

Lines contain exact text, optional recognition confidence in `[0,1]`, and optional
`box: {x,y,width,height}` in normalized coordinates. Boxes require a
`sourceImageId` naming the **exact image** that was read. A crop/rotation/resize
creates a new source image identity. A full-page OCR box belongs to a line;
the engine never pretends it knows a word or character box.

Field evidence contains a page ID, observation ID, line ID, exact text offsets,
source quote and available source box. `resolveEvidence` verifies the offsets and
quote. `rawValue` preserves the reading; `value` is a separately normalized value.

## Decisions and review

- A supported type needs a heading plus its field structure. Mentions in prose
  do not establish the type. Conflicting headings stay unknown.
- Adjacent pages join only with the same explicit reference and compatible
  available parties. Different references/types stay separate. Unreadable and
  unclassified pages remain accounted for, with boundary review where needed.
- Conflicting readings remain unresolved even if a majority agrees. Recognition
  scores and agreement are not calibrated correctness probabilities.
- Invoice arithmetic uses integer minor units for two-decimal amounts. Ambiguous
  separators/dates/currencies and missing fields stay for review. Other currency
  precisions and complex discounts/credits are outside the initial profile.
- `supported` means the source and rules support a candidate. Automatic filing is
  disabled throughout this experimental version, including after confirmation.
- `confirmField` requires the document, current review revision, source evidence,
  expected readings, and explicit confirmation. It returns a new result, keeps
  the original quote, records a human correction, and invalidates previous checks.
- Corrections are excluded from model training by default. Exporting a review and
  approving examples for training are separate explicit operations.

`buildRereadRequests` produces bounded source-line regions for disputed fields.
`rereadRegions` invokes a host-supplied recognizer on those regions, preserves all
earlier observations, supports cancellation, and records failed attempts. It
does not fabricate regions for text-only input or overwrite manual corrections.

## Host responsibilities

The host resolves original image IDs, preserves originals, provides OCR if needed,
and handles authentication, tenant isolation, durable storage and user-directed
filing. This package makes none of those decisions. A JSON export contains text
and geometry; the host must retain the referenced images to reopen visual proof.

Before automatic acceptance: gather labeled real documents, split by company and
layout, evaluate unseen documents, and calibrate false-accept rates per field.
