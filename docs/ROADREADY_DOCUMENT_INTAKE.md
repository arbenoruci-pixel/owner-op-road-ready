# File a document for Arben or Shkumbin

The private RoadReady workspace holds the originals, trip instructions, history and balances. Work from the carrier identity, registered operator and connected inboxes specified in the private task configuration. Use the same workflow for real email attachments and files the carrier supplies in chat. The carrier uses the dispatch link inside the existing RoadReady account. A leased operator uses the separate operator login.

## Identify the document and its owner

| Incoming document | Verify before filing | File and subsequent action |
| --- | --- | --- |
| Rate confirmation or revision | Driver named on the tender, an explicit assignment from the carrier, or the uniquely assigned broker and load number. Inspect every page for stops, reference numbers, local times, reefer settings, rate and exceptions. | Store the original on that operator's load. Publish the ordered pickup and delivery instructions. Keep earlier revisions. |
| BOL or signed POD | Match broker/load reference and stops to an existing assignment. Check pages, signatures, final delivery and exceptions. | Add it to the same load. Once delivery and all billing evidence are verified, build the invoice packet and use the existing FirstLine send claim. |
| Mudflap receipt | Verify the original sender, transaction ID, purchase date, driver or assigned unit, actual payer and final amount after discounts. | Store the receipt as expense evidence. Post the charge once to the correct ledger. A station copy corroborates the same transaction. |
| Cab or wallet document | Identify the actual driver, vehicle or explicitly covered equipment, document type, issuer, version and any printed expiry. | Store the original in the assigned wallet. Preserve the previous version and distinguish expired documents. |
| FirstLine acknowledgement or remittance | Match the invoice identity, amount and payee. | Record receipt or funding at its own stage. The operator's payout has its own bank evidence. |

“Narta Express” on a broker document applies to both drivers. An inbox address, an email subject or a stop near a fuel purchase is insufficient to decide ownership. Check the legacy owner load references as well as the new workspace before creating a load or invoice. Do not automatically generate new bills for historical freight whose payment status is unresolved. A document common to both cabs may be shared only when its coverage and the carrier's instructions actually apply to both. Preserve wallet and load access per operator.

## Email and files handed over in chat

1. Preserve the actual attachment or carrier-supplied file. Record its immutable provider reference and attachment part, and calculate its SHA256. Use distinct prefixes for Gmail, Outlook and chat. For a file the carrier supplied here, use its real file ID or conversation/message/attachment reference prefixed with `chat:`. The owner's forwarding email remains the envelope sender when the owner forwards a POD. Keep the original file bytes and actual source. A pasted link or preview is insufficient evidence of a complete original.
2. For load documents, follow [the load procedure](TOLAJ_CHATGPT_OPERATIONS.md). Call `rr_lease_stage_load` for the positively identified operator and normalized broker/load identity. Upload through the original-file helper. File a private handoff with `rr_lease_apply_intake(document_id,'owner_upload',source_reference,NULL,assignment_evidence,reviewed_fields,previous_ratecon_id,verified_for_billing)`. Use `rr_lease_apply_mail` for email, recording the actual sender. Record assignment evidence from the carrier or the document. Never invent an email address for a file handed over in chat.
3. For cab documents and fuel evidence, use [the wallet procedure](LEASE_OPERATOR_WALLET.md). Compare size and checksum after upload. For a body-only Mudflap receipt, archive the supported mailbox record with the provider ID, actual headers and body. A correction of an old receipt or rate uses the original identity and a version or adjusting entry. Keep the audit trail.
4. When a document's assignment or readability needs a decision, upsert only the source locator, attachment locator and concrete reason into `rr_lease_private.intake_review`. Preserve the source in its original private inbox or chat file. The key is `(carrier_user_id,source_ref,attachment_ref)`. Update an existing reason only while unresolved. Record `notified_at` after requesting the missing fact once. Revisit these entries even when the original message has fallen outside the mailbox search window. Resolve with the verified load or wallet document ID and actual resolution timestamp.
5. For periodic mailbox checks, take a UTC upper bound at the start, scan the relevant received folders in pages from the prior checkpoint with overlap, and reconcile across both mailboxes and chat. Record `rr_lease_private.mailbox_cursors.checked_through` only when all matching messages in the window are filed or individually held for review. Advance monotonically using `greatest` on conflict. An empty window can advance. A connector error leaves the cursor where it was. On first activation include outstanding assigned freight and recent operational documents. Reconcile older history against the previous load and invoice records before creating a financial effect.

## What the two drivers see

The carrier workspace records Arben's own freight at its approved gross with his evidenced expenses. The carrier can also review the leased operator. Shkumbin sees his own loads, original paperwork, wallet, daily activity and weekly statements. For Tolaj the agreed split is 92% to the operator and 8% to Narta. A documented, authorized Narta-paid advance is deducted once. Fuel and ELD paid directly by Tolaj have zero effect on the payout. Unknown expenses stay pending or deferred. Record the real receipt date and verified payment deadline independently of factoring.

Before a FirstLine submission, reconcile the prior invoice and the fixed sending mailbox's Sent Items across both workflows. Use the single database send claim for the exact packet. Keep wallet records, fuel receipts and operator pay details out of the factoring packet unless an item is specifically required and approved for billing. Prepare the itemized pay statement for Arben. Record a completed payout only against its actual bank date, a valid reference and the matching transferred amount.
